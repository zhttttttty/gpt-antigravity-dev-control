# ADR-006：完整配置安装、安全目标选择和实时任务总览

状态：2026-10-28 按用户“根据文档优化项目并清理”的授权实施，作为本次实现约定。

## 问题

普通 init 的最小运行状态有效，但显式安装 Codex profile 没有配套 `.ai/config.yaml`，
导致按文档安装后仍无法通过离线配置检查。原 profile 复制还会覆盖已有配置。
统一入口在缺少 --repo 参数值或目标不存在时可能输出 traceback；相对 init 路径会被重复解析。
显式 --repo 指向子目录时，任务命令可能静默操作外层 Git 仓库。
人工 PROJECT_STATE 摘要不能表达实时任务总览，但空 active_tasks 并不自动构成错误。

## 决策

- 保留普通 init 的最小行为；显式 profile 安装同时复制分发的 `.ai/config.yaml`。
- 安装前检查所有 profile 目标，存在不同内容时拒绝，只有显式
  `--overwrite-codex-profile` 才允许覆盖冲突；相同内容不重写，不覆盖自定义项目说明和任务模板。
- profile 目标拒绝符号链接、目录联接及文件/目录类型冲突，避免写入目标之外。
- 显式 --repo 对任务命令必须等于 Git 根目录；不指定时仍保留从当前目录查找 Git 根的行为。
  init 本身也要求实际 Git 根目录，check-orchestration 继续允许检查没有独立 Git 的配置夹具。
- `status --json` 从任务目录读取六类状态、计数、进行中任务和全部未完成任务，
  验证基本身份和目录一致性；保留默认文本及单任务 JSON 输出，不改写人工摘要。
- 配置检查缺少输入时只报告文件错误，避免大量派生的 None/None 比较。
- 保持 schema v2、状态迁移、审批、Scope、回执与 DONE 门不变。

## 兼容性与验证

以前使用 --repo 指向普通子目录的调用需改传 Git 根目录；原配置夹具 status 示例移除。
原来依赖隐式覆盖 profile 的调用需先审查差异，再显式传覆盖参数。
这些是 CLI 行为收紧，运行版本更新为 3.3.1-local。
离线测试验证初始化、冲突预检、参数和目标边界、状态读取及原协议回归，不证明模型服务可用。

本次在已有未提交文档的外层仓库直接修复工具；将全部既有工作强制提交后再委派的成本较高，
因此没有启动 agy 或原生 worker，也没有复用或改写历史任务的回执。

## 回滚

回滚本次脚本、测试、文档和 VERSION；恢复前比较用户后续修改。
新增 `.codex/` 和 `.ai/config.yaml` 只包含分发默认值，删除或还原前检查是否已被用户定制。
不重置历史任务或工作树，不用夹具通过替代真实项目和运行时验证。
